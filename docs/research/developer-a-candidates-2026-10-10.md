## Collection and limits

- Established candidates were chosen for complementary documented interfaces; this is a curated pool, not a popularity leaderboard.
- Recent-project query: `language:Python created:>=2026-04-10 stars:>=100 archived:false fork:false`, through connected GitHub search. Six returned repositories were inspected; ranking and completeness were not independently established.
- Trending source: [weekly GitHub Trending](https://github.com/trending?since=weekly). Five rows were sampled for capability variety, not the top five. The production adapter separately passed a live one-repository page/metadata smoke check.
- HEAD identities were read with `git ls-remote`; their collection timestamps are in local `candidate-commits.json`. README/license evidence came from connected GitHub file reads at those exact commits, usually the first 160 lines. Full-file bytes/integrity were not independently verified for these connector excerpts. SHA-256 in these research snapshots identifies captured text, not full files.
- Initial research snapshot timestamps represent local preparation time, not exact GitHub request times. Public links below remain inspectable; raw local artifacts are ignored, not a durable Neon corpus.
- `python-icalendar/icalendar` could not be resolved and was replaced with the verified `collective/icalendar` repository. License links show inspected evidence, not full dependency-license approval.

## Five hypotheses and critique

Five unique pairs have retained HF previews. The following boundaries are reviewed interpretations; an HF proposal is not proof of compatibility. Failed requests, unsupported citations and invalid proposals were retained locally alongside successful retries.

| Pair | Candidate workflow | Existing overlap / criticism | Decision |
| --- | --- | --- | --- |
| MarkItDown + icalendar | Candidate idea was iCalendar-to-Markdown. | MarkItDown does not document accepting the model-proposed calendar object. [A published scheduler script](https://gist.github.com/anjohan/9b60eef8faed7d99ea6405ab52657e01) already combines document conversion with calendar output. A document-to-event variant would need event parsing and timezone rules. | Reject the proposed interface as unsupported; do not select now. |
| Trafilatura + Datasette | Fixed HTML → extracted text/metadata → explicitly mapped SQLite rows → searchable UI. | [Datasette’s LLM plugin directory](https://llm.datasette.io/en/latest/plugins/directory.html) lists Trafilatura-backed site-text fragments and Datasette tools. | NetworkX + Altair | Convert graph nodes/edges/metrics to visualization tables. | [altair-nx](https://github.com/T-Flet/altair-nx) already wraps this exact pair. Generic graph visualization would duplicate existing work; the extracted NetworkX interface remains unclear. | Reject generic graph-viewer direction. |
| sqlite-utils + Frictionless | Validate original tabular rows before gated SQLite insertion. | The HF preview incorrectly suggests converting a validation report into insertion data. Keep the original rows and use the report as a gate. [sqlite-utils](https://sqlite-utils.datasette.io/en/stable/python-api.html) and [Frictionless](https://framework.frictionlessdata.io/docs/guides/validating-data) already provide the individual primitives. | Possible fallback; less visible source-provenance interaction. |
